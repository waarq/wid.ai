# WIT frontend conventions

Read this before writing code. The PRD (`PRD.md`) decides product and stack questions; this file covers how we build.

## 1. Stack versions

Next.js 16.3.8 (App Router, Turbopack), React 19.2.8, TypeScript 5.9 (strict), Tailwind CSS v4 (CSS-first config, `@tailwindcss/postcss`, no `tailwind.config.js`), TanStack Query 5.104, Zustand 5, Zod 3.25, React Hook Form 7, Framer Motion, Lucide, shadcn/ui on `radix-ui`, Sonner, next-themes.

Version-matched docs are in `node_modules/next/dist/docs/`. Check them before using any Next.js API from memory.

## 2. Next.js 16 changes that differ from older habits

| Area | What changed in 16 | What we do |
| --- | --- | --- |
| Middleware | `middleware.ts` is deprecated and renamed **`proxy.ts`**, which exports `proxy` (not `middleware`). Proxy always runs on Node.js. Setting `runtime` throws, and edge is not supported. Config flags were renamed too (`skipMiddlewareUrlNormalize` became `skipProxyUrlNormalize`). | Put route guarding in `src/proxy.ts`. With a `src/` dir it **must** live in `src/`. `matcher` values must be literal constants. Exclude `_next/static`, `_next/image` and public assets. Proxy only gives routing hints. Authorization is enforced by the backend. |
| Request APIs | Synchronous access has been removed. `params` and `searchParams` (page, layout, route, default, OG/icon images) are **Promises**, and so are `cookies()`, `headers()` and `draftMode()`. | `const { meetingId } = await props.params`. Type pages with the global `PageProps<'/my-calls/[meetingId]'>`, layouts with `LayoutProps<'/...'>` and route handlers with `RouteContext<'/...'>`. These are generated by `next dev`/`next build`/`next typegen` and need no import. |
| Bundler | Turbopack is the default for `dev` **and** `build`. A custom `webpack` config makes `next build` fail. | Don't add webpack config. `next dev` writes to `.next/dev`, which is why tsconfig includes `.next/dev/types`. |
| Lint | `next lint` is gone, `next build` no longer lints, and the `eslint` key in `next.config` was removed. ESLint uses flat config. | Run `npm run lint` (plain `eslint`). |
| Env | `serverRuntimeConfig`/`publicRuntimeConfig` were removed. `NEXT_PUBLIC_*` is inlined at build time **only when accessed literally**. | Always write `process.env.NEXT_PUBLIC_API_URL`, never `process.env[name]` or destructuring. `.env*` files stay in the project root, not `src/`. |
| Caching | PPR moved to `cacheComponents: true` (`experimental.ppr` was removed). `revalidateTag(tag, profile)` now needs a second argument. New APIs: `updateTag` (read-your-writes, Server Actions only), `refresh()`, `'use cache'`, `cacheLife`, `cacheTag`. | Not enabled. App data is client-side through TanStack Query. If `cacheComponents` is ever turned on, queries needed for the first render must sit behind `<Suspense>`. |
| Parallel routes | Every `@slot` needs an explicit `default.tsx`, or the build fails. | Add `default.tsx` that returns `null` for any modal slot. |
| `next/dynamic` | `ssr: false` is rejected in Server Components. | Put `dynamic(() => import(...), { ssr: false })` inside a Client Component. |
| Images | Local `src` with a query string needs `images.localPatterns.search`. Defaults changed: `minimumCacheTTL` is 4h, `16` was removed from `imageSizes`, and `qualities` defaults to `[75]`. `images.domains` is deprecated in favour of `remotePatterns`. | Use static imports or plain public paths. |
| Scroll | Next no longer forces `scroll-behavior: auto` during navigation. | Add `data-scroll-behavior="smooth"` on `<html>` only if we set smooth scrolling globally. |
| React 19.2 | `<ViewTransition>`, `useEffectEvent`, `<Activity>`. React Compiler support is stable but **off** by default (`reactCompiler`). | Don't hand-memoize by reflex. Use `useMemo` and `useCallback` only where profiling shows a need. |
| TS plugin | It flags function props on Client Components unless the prop is named `action` or ends in `Action`, because only Server Functions can cross the boundary. | Never pass handlers from a Server Component. Pass data or `children` instead. |
| Metadata | `themeColor`/`colorScheme`/`viewport` in `metadata` are deprecated. | Use `export const viewport`. |
| Runtime | Node 20.9+, TS 5.1+. Browser floor is Safari 16.4 / Chrome 111. | Avoid APIs newer than that baseline. For example `AbortSignal.any` is Safari 17.4, so `lib/api` links signals by hand. |

## 3. Server and client boundary

- Server Components are the default. Marketing pages stay fully server-rendered.
- Add `"use client"` only for state, effects, browser APIs, event handlers or Framer Motion. Put it on the smallest leaf that needs it, never on a page root.
- Props that cross into a Client Component must be serialisable. To nest server output inside a client wrapper, pass it as `children` or another slot.
- Providers live in `src/components/providers/app-providers.tsx`. Render them from the nearest shared layout that needs them: the `(app)` and onboarding layouts, not marketing.
- TanStack Query client: `makeQueryClient()` creates a fresh client per server render and `getQueryClient()` returns a browser singleton (`src/lib/query/client.ts`).
- Heavy interactive pieces load with `next/dynamic`: audio player, assistant, command palette and charts.

## 4. Where things live (`src/`, alias `@/*`)

```
app/                 routes only: (marketing), (auth), onboarding, (app)
components/ui/       shadcn primitives (do not restyle ad hoc)
components/shared/   EmptyState, ErrorState, LoadingState, StatusBadge, ...
components/<domain>/ feature components (meetings, transcript, assistant, deals, ...)
hooks/               TanStack Query hooks: useMeetings(), useShareMeeting(), ...
store/               Zustand: UI-only state (ui, onboarding draft, capture, preferences)
types/               domain model; import from "@/types"
services/interfaces/ one interface per service
services/mock/       Mock* implementations (read mock-data/, simulate latency)
services/api/        Api* implementations (use lib/api apiClient)
services/registry.ts `services` container + mock/api switch
mock-data/           fictional fixtures; only services/mock imports these
lib/api/             apiClient, adapters, HTTP error mapping
lib/query/           query client factory + queryKeys
lib/utils/errors.ts  AppException, toAppError, isAppError, user-safe messages
```

Data flows **UI → hook → `services.x` → Mock* or Api***. Components never import `mock-data/`, `services/mock`, `services/api` or `apiClient`. Server data belongs in TanStack Query, never in Zustand.

## 5. Adding or implementing a service

1. Model the data in `src/types/<domain>.ts` and export it from `src/types/index.ts`. Put inputs and params next to the entity, as `Create*Input`, `Update*Input` and `*ListParams`.
2. Declare the interface in `src/services/interfaces/<name>-service.ts`. Every method returns a Promise. Collections return `ListResponse<T>`.
3. Add it to `ServiceRegistry` in `services/registry.ts`, together with its getter in `createServices`.
4. Implement `Mock<Name>Service` in `services/mock/` and `Api<Name>Service` in `services/api/`. Register their factories in the `serviceFactories` slots.
5. Add keys to `lib/query/keys.ts`, then write hooks in `hooks/` that call `services.<name>`.
6. Errors: implementations reject **only** with `AppException` (`lib/utils/errors.ts`). `apiClient` already guarantees this. Mocks construct one explicitly. Never surface a backend message. UI copy comes from the screen plus `error.message`, which is always user-safe.
7. Switch implementations with `NEXT_PUBLIC_USE_MOCKS` (`false` means API).

## 6. Traceability rule

Every AI-generated insight extends `Traceable { meetingId, sourceSegmentId, sourceTimestamp }`. That covers `Decision`, `ActionItem`, `Question`, `Risk`, `KeyMoment`, `DealSignal`, `PlaylistItem`, assistant `AnswerSource`, and transcript, decision and action search results. Without evidence a value is not a valid insight.

- `sourceTimestamp` is in **seconds**. Durations are seconds and dates are ISO strings (`ISODateString`), or `ISODate` for due dates.
- Each of these renders a "Source: <meeting> · mm:ss · Jump to conversation" affordance through one shared component. Jumping seeks the player and scrolls to `sourceSegmentId`.
- `TranscriptSegment.speakerId` equals `Participant.id`.

## 7. Product rules encoded in types

- Capture is always manual. `CaptureSettings.manualCapture` is the literal `true`. No service method starts a capture without a user action.
- Privacy defaults: `sharingPreference` defaults to `"only_me"` and `capturePreference` to `"manual"` (`ONBOARDING_DEFAULTS`). Always show a meeting's visibility.
- Offer "Anyone with the link" only when `ShareSettings.linkSharingAvailable` is true.
- `MeetingStatus` (server record) and `CaptureStatus` (client session) are separate state machines. The pre-capture "Ready" is `ready_to_capture`. The processed "Ready" is `ready`.
- Permissions (`canManage`, `canRemove`) are computed by the backend and never derived in the UI.

## 8. Design system rules

- **Type**: Geist Sans plus Geist Mono through `next/font` (`src/lib/fonts.ts`). Never Inter. Use mono for timestamps, durations and numeric metrics, with tabular figures.
- **Icons**: Lucide only. **No emojis anywhere**, including copy and mock data. Key moments use fixed icons: Decision `Gavel`, Commitment `Handshake`, Risk `TriangleAlert`, Question `CircleQuestionMark`, Insight `Lightbulb`. These names were checked against the installed lucide-react, where `CircleHelp` no longer exists. Define the mapping once in a shared map.
- **Motion**: Framer Motion only (no GSAP). Use spring physics. Animate `transform`/`opacity` only. Honour `prefers-reduced-motion` with `useReducedMotion` or `motion-safe:`. Don't animate large lists.
- **Color**: one muted emerald accent. Use a warm off-white and a tinted near-black, never pure `#000`/`#fff`. Colors come from tokens in `globals.css`, never raw hex in components.
- **Surfaces**: prefer hairline 1px dividers over cards. Keep radii small (6 to 8px). Avoid generic card grids and rows of three equal cards. Avoid heavy shadows, glass effects and gradients.
- **States**: use skeleton loaders, not spinners, for page and section loads. Every interactive element gets tactile `:active` feedback, for example a subtle `active:scale-[0.98]`. Every important interaction has loading, empty, error and success states.
- **Layout**: use `min-h-[100dvh]`, never `h-screen`. Use CSS grid instead of flexbox percentage math. Support 320px to 1920px. Tables turn into cards on mobile.
- **Demo names**: use only the PRD's fictional companies: Northstar Labs, Vertex Digital, Atlas Properties, Crescent Health and **Meridian Freight** (replacing "Acme"). Never use "Acme". People come from the PRD list (Ahmed Khan, Ayesha Malik, Hamza Siddiqui, Sara Ahmed, Usman Raza, Fatima Noor, Ali Hassan, Hira Shah) plus the demo user Waleed Ahmed (`waleed@wit-demo.com`). Label demo content as demo.

## 9. Security

- No secrets in code or `NEXT_PUBLIC_*`. No credentials in `localStorage`. Sessions use backend httpOnly cookies, and the fetch adapter sends `credentials: "include"`. For header auth, register a token source with `setAuthTokenProvider`, which keeps the token in memory or the auth SDK.
- Client state and proxy redirects are only UX. Treat backend authorization as authoritative.
